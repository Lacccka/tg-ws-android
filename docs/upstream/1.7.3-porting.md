## Immediate next-task Android change list

The next task should limit runtime code changes to WebSocket keepalive support:

1. Add outbound PING support to the live WebSocket abstraction.
    - Add a `sendPing(payload: ByteArray = ByteArray(0))`-style method to
      `RawWebSocket` using a masked `RawWebSocketCodec.OP_PING` frame.
    - Add the corresponding method to `WebSocketBinaryStream` and implement it in
      `RawWebSocketBinaryStream`.
2. Add a keepalive interval field with upstream defaults/semantics.
    - Add `wsKeepaliveIntervalSeconds` or equivalent to `ProxyServerConfig`,
      defaulting to `30.0` seconds.
    - Clamp negative configured values to disabled/zero semantics like upstream
      `max(0, args.ws_keepalive)`.
    - Do not add UI controls in the keepalive task unless separately requested.
3. Start a keepalive companion thread/task in `BridgeSession` or at the
   `runWebSocketRoute(...)` call boundary.
    - Non-positive interval disables the loop.
    - Use a reasonable minimum of one second for positive intervals, matching
      upstream `max(1.0, interval)`.
    - Send PING periodically and end/close the session on send failure so stale
      upstream connections are detected without waiting for the next client
      packet.
4. Add/adjust unit tests around outbound PING frame generation and the bridge
   keepalive lifecycle.

Do **not** modify route selection, fallback policy, pool logic, Cloudflare
policy, DC mapping, UI, foreground service, or proxy lifecycle as part of the
keepalive port.

## Uncertainty / follow-up

- The upstream keepalive issue reference says the goal is keeping idle upstream
  flows warm and detecting dead upstreams promptly. Android should preserve that
  intent, but the exact threading placement should be chosen carefully so it does
  not alter existing route selection, fallback, pool, or lifecycle behavior.
- Existing Android `RawWebSocketCodec` already has PING/PONG opcodes and frame
  building support, so most of the next-task raw WebSocket work should be in the
  live `RawWebSocket` wrapper rather than the codec.
- Logging/diagnostics changes in v1.7.3 are intentionally deferred as “check
  later” because they are not required for the immediate keepalive runtime port.
